# bubai 相比 Codex / Claude Code 等传统 Agent 工具的核心优势

## 概述

Codex、Claude Code 等传统 Coding Agent 工具本质上是**单人单 Agent 的线性对话工作台**；而 bubai 将人机协作升级为**多人多 Agent 共享上下文的协作总线**，在跨 Agent 接力与上下文复用上具备原生架构优势。

---

## 核心优势

### 1. 多对多协作与跨 Agent 无缝接力（M:N 协作）

* **传统工具的痛点**：
  Codex、Claude Code 等采用的是「单人 × 单 Agent（1:1）」的孤岛模式。当一个任务在 Codex 里推进到一半，想要切给 Claude 做代码审查，或让 AGY 接手下一步实现时，缺乏原生的跨 Agent 交接机制，只能靠人工复制粘贴上下文、重新交代背景，切换和协同成本高。
* **bubai 的优势**：
  天然支持「多人 × 多 Agent（M:N）」在同一个协作空间内共事。不同模型、不同专长的 Agent 共处同一语境，可以按阶段直接 `@` 接力推进（例如：规划 → 编码 → 审查 → 验收），团队成员也可以随时介入补充信息或决策，无需人工搬运上下文。

### 2. Channel 共享上下文 + Session 灵活执行（免分叉复用上下文）

* **传统工具的痛点**：
  上下文强绑定在单一的线性会话（Thread）中。如果想基于同一段背景复用上下文，或并行探索不同方案，通常必须手动分叉（fork thread）；分叉之后各分支彼此割裂，后续进展难以回流和汇总。
* **bubai 的优势**：
  将「共享上下文（Channel）」与「具体执行（Session）」解耦。Channel 充当持续沉淀的公共上下文基座，多个 Session 可以直接锚定同一份 Channel 上下文启动和运行——既不需要反复 fork thread 来“复制记忆”，各 Session 的执行结果也能自然回流到同一个 Channel 中，供人与其它 Agent 继续复用。

---

## 核心对比

| 对比维度 | Codex / Claude 等单点工具 | bubai |
| :--- | :--- | :--- |
| **协作拓扑** | 1 人 × 1 Agent（单兵工作台） | 多人 × 多 Agent（团队协作空间） |
| **跨模型 / Agent 接力** | 割裂，需人工复制粘贴搬运上下文 | 原生接力，同语境下直接 `@` 移交 |
| **上下文复用方式** | 强绑定单 Thread，复用需手动 fork，分支难合并 | Channel 沉淀共享上下文，按需起 Session，天然复用与回流 |

---

## 一句话总结

> Codex / Claude 等工具是**单人单 Agent 的线性对话工作台**；而 bubai 把对话升级为**多人多 Agent 共享上下文的协作总线**，让跨 Agent 接力和上下文复用成为原生能力。
